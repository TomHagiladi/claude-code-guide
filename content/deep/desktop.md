## שלוש הלשוניות - איפה Code יושב

באפליקציית הדסקטופ יש שלוש לשוניות בחלק העליון. הן שלושה מוצרים שונים, לא שלושה מצבים של אותו דבר:

| הלשונית | מה זה | גישה לקבצים |
|---------|-------|--------------|
| **Chat** | שיחה רגילה, כמו claude.ai | אין |
| **Cowork** | סוכן שרץ ברקע ב-VM מבודד, על המחשב או בענן | בסביבה מבודדת משלו |
| **Code** | Claude Code המלא, עם גישה ישירה לקבצים שלך | מלאה |

הדף הזה עוסק **רק בלשונית Code**. הלשוניות Chat ו-Cowork מתועדות במרכז התמיכה של Claude, לא בתיעוד המפתחים.

### האפליקציה כוללת את Claude Code

נקודה שחוסכת בלבול: **אין צורך להתקין Node.js או את ה-CLI בנפרד**. האפליקציה מגיעה עם Claude Code בתוכה. התקנת ה-CLI נדרשת רק אם רוצים להריץ `claude` מהטרמינל בנוסף.

### שני מספרי גרסה נפרדים

זו מלכודת קלה: לאפליקציית הדסקטופ יש מספור גרסאות **משלה**, שאינו קשור למספור של Claude Code.

- האפליקציה מתקדמת בסדרת `v1.xxxx.0` - למשל מערכת הפאנלים דורשת `v1.2581.0` ומעלה
- מנוע Claude Code מתקדם בסדרת `v2.1.x`

כשמשהו "לא עובד למרות שזה בתיעוד" - השאלה הראשונה היא איזו משתי הגרסאות בדקת. את גרסת האפליקציה רואים ב-`Help → About` ב-Windows, או ב-`Claude → About Claude` ב-macOS. לחיצה על מספר הגרסה מעתיקה אותו.

## התקנה ודרישות

### מנוי

לשונית Code דורשת מנוי בתשלום: **Pro, Max, Team או Enterprise**. בחשבון חינמי הלחיצה על הלשונית מובילה לעמוד שדרוג.

### הורדה

| מערכת | קישור |
|--------|--------|
| macOS (אוניברסלי, Intel ו-Apple Silicon) | `claude.ai/api/desktop/darwin/universal/dmg/latest/redirect` |
| Windows x64 | `claude.ai/api/desktop/win32/x64/setup/latest/redirect` |
| Windows ARM64 | `claude.ai/api/desktop/win32/arm64/setup/latest/redirect` |
| Linux (בטא) | דרך `apt` או `.deb`, לאובונטו ודביאן |

### Git ב-Windows - חובה, לא המלצה

זו הדרישה שהכי הרבה אנשים נתקלים בה:

> **ב-Windows, בלי Git מותקן לשונית ה-Code לא עובדת בכלל.** לא "מומלץ" ולא "כדאי" - חובה. מתקינים את Git for Windows ואז **מפעילים מחדש את האפליקציה**.

ההבדל מול ה-CLI מהותי: ב-CLI על Windows אפשר לעבוד בלי Git (יש נפילה חזרה ל-PowerShell, ראה [powershell_tool.md](#/deep/powershell)). בדסקטופ אי אפשר, כי בידוד הסשנים בנוי על Git worktrees והוא לא אופציונלי.

ב-macOS רוב המחשבים מגיעים עם Git מותקן. בדיקה: `git --version` בטרמינל.

אם המאגר משתמש ב-Git LFS, צריך גם אותו - השגיאה תגיד זאת במפורש.

## פתיחת סשן - ארבע הבחירות

לפני ההודעה הראשונה בוחרים ארבעה דברים באזור הפרומפט. כולם ניתנים לשינוי תוך כדי, חוץ מהתיקייה:

1. **סביבה** (Environment) - איפה Claude רץ בפועל: Local, Cloud, SSH או WSL
2. **תיקיית פרויקט** - התיקייה או המאגר שבו עובדים. בסשני ענן אפשר לצרף כמה מאגרים
3. **מודל** - מהתפריט הנפתח שליד כפתור השליחה
4. **מצב הרשאה** - כמה אוטונומיה יש ל-Claude

התיקייה ננעלת לסשן. אין בדסקטופ מקבילה לפקודה `/cd` של הטרמינל - כדי לעבוד בתיקייה אחרת פותחים סשן חדש.

### תיבת הפרומפט

- **Enter** שולח. אפשר לתקן תוך כדי ריצה: כפתור העצירה קוטע מיד, ואילו הקלדת תיקון ו-Enter שולחת אותה **בלי לעצור** - Claude קורא אותה ברגע שהפעולה הנוכחית מסתיימת ומתקן לפני הצעד הבא
- **`@` ואז שם קובץ** מכניס קובץ להקשר, עם השלמה אוטומטית. לא זמין בסשני ענן ו-WSL
- **כפתור ה-`+`** פותח: צירוף קבצים, skills, connectors ו-plugins
- **גרירה ושחרור** של תמונות ו-PDF ישירות לתיבה - שימושי לצילומי מסך של באגים או למוקאפים

## ארבע סביבות ההרצה

<div class="plain-language">
<h4>במילים פשוטות</h4>

<p>"סביבה" זו התשובה לשאלה <strong>על איזה מחשב Claude באמת עובד</strong>. הממשק תמיד אצלך, אבל המנוע יכול לרוץ במקום אחר לגמרי.</p>

<p><code>Local</code> זה המחשב שלך - זה מה שתשתמש בו ב-99% מהמקרים. <code>Cloud</code> זה שרת של Anthropic, והיתרון היחיד שלו הוא שאפשר לסגור את המחשב והעבודה ממשיכה. <code>SSH</code> זה שרת מרוחק שלך, ו-<code>WSL</code> זה לינוקס שרץ בתוך Windows.</p>
</div>

| הסביבה | איפה רץ | ממשיך אחרי סגירת האפליקציה |
|---------|----------|------------------------------|
| **Local** | המחשב שלך, גישה ישירה לקבצים | לא |
| **Cloud** | תשתית מנוהלת של Anthropic | כן |
| **SSH** | מכונה מרוחקת שלך, דרך SSH | כן (רצה על המכונה המרוחקת) |
| **WSL** | הפצת לינוקס בתוך Windows | לא |

### Local - מלכודת משתני הסביבה

זו נקודה שמייצרת תקלות שקשה לאבחן: **האפליקציה לא יורשת את כל סביבת ה-shell שלך**.

- ב-**macOS**, כשמפעילים מה-Dock או מ-Finder, האפליקציה קוראת את פרופיל ה-shell (למשל `~/.zshrc`) אבל שולפת ממנו רק את `PATH` וקבוצה קבועה של משתני Claude Code. משתנים אחרים שייצאת שם **לא נקלטים**
- ב-**Windows**, האפליקציה יורשת משתני משתמש ומערכת, אבל **לא קוראת פרופילי PowerShell**

הפתרון הנכון הוא **עורך הסביבה המקומית**: פותחים את תפריט הסביבה בתיבת הפרומפט, מרחפים מעל `Local`, ולוחצים על סמל גלגל השיניים. משתנים שנשמרים שם מוצפנים על המכונה וחלים על **כל סשן מקומי וכל שרת פיתוח**.

לחלופין אפשר להוסיף למפתח `env` ב-`~/.claude/settings.json`, אבל שים לב: אלה מגיעים לסשני Claude בלבד ו**לא** לשרתי הפיתוח.

זו גם הסיבה לתקלה הנפוצה "Claude לא מוצא את npm" - הכלי עובד בטרמינל הרגיל, אבל האפליקציה לא ירשה את ה-`PATH` שמוביל אליו.

### Cloud

- ממשיך לרוץ גם אחרי סגירת האפליקציה או כיבוי המחשב
- השימוש נספר במכסת המנוי, בלי חיוב חישוב נפרד
- תומך ב**כמה מאגרים בסשן אחד** - לוחצים על `+` ליד תג המאגר, וכל מאגר מקבל בורר ענף משלו. שימושי לשינוי בספרייה משותפת ובצרכנים שלה במקביל
- אפשר ליצור סביבות ענן מותאמות עם רמות גישה לרשת ומשתני סביבה, דרך `Add cloud environment`
- אפשר לנטר אותם גם מ-claude.ai/code ומאפליקציית המובייל

### SSH

מוסיפים חיבור מתפריט הסביבה, `+ Add SSH connection`. הדיאלוג מבקש:

| השדה | משמעות |
|------|---------|
| `Name` | תווית ידידותית |
| `SSH Host` | בתבנית `user@hostname`, או שם מארח מתוך `~/.ssh/config` |
| `SSH Port` | ברירת מחדל 22 |
| `Identity File` | נתיב למפתח פרטי. ריק = המפתח הדיפולטי או ההגדרה מ-config |

המכונה המרוחקת חייבת להריץ Linux או macOS. **האפליקציה מתקינה שם את Claude Code אוטומטית** בחיבור הראשון. סשני SSH תומכים במצבי הרשאה, connectors, plugins ו-MCP.

מנהלי מערכת יכולים להפיץ חיבורים לצוות דרך `sshConfigs` בקובץ managed settings:

```json
{
  "sshConfigs": [
    {
      "id": "shared-dev-vm",
      "name": "Shared Dev VM",
      "sshHost": "user@dev.example.com",
      "sshPort": 22,
      "sshIdentityFile": "~/.ssh/id_ed25519",
      "startDirectory": "~/projects"
    }
  ]
}
```

חיבורים שמוגדרים כך מופיעים אצל המשתמש כמנוהלים - הוא יכול לבחור בהם אבל לא לערוך או למחוק.

להגבלת היעדים יש `sshHostAllowlist`:

```json
{
  "sshHostAllowlist": ["*.devboxes.example.com", "bastion.example.com"]
}
```

מערך ריק מבטל סשני SSH לגמרי. ההגדרה נקראת **רק** מ-managed settings, ומכובדת **רק** על ידי אפליקציית הדסקטופ - ה-CLI ותוספי ה-IDE מתעלמים ממנה, והיא גם לא חוסמת פקודות `ssh` שרצות דרך כלי ה-Bash. כלומר זו הגבלה על האפליקציה, לא גבול רשת.

### הטרמינל המובנה

נפתח ב-**Ctrl+`** בשתי מערכות ההפעלה, או מתפריט Views. הוא נפתח **בתיקיית העבודה של הסשן וחולק את אותה סביבה** עם Claude - כלומר `npm test` או `git status` רואים בדיוק את אותם קבצים ש-Claude עורך.

- `+` בכותרת הפאנל פותח לשונית טרמינל נוספת
- לחיצה ימנית על תיקייה בצ'אט ובחירת `Open in terminal` פותחת שם טרמינל חדש
- זמין בסשנים מקומיים בלבד

### עורך הקבצים

לחיצה על נתיב קובץ בצ'אט או ב-diff פותחת אותו בפאנל. נתיבי HTML, PDF, תמונה ווידאו נפתחים בפאנל הדפדפן במקום.

- עריכות נקודתיות ואז **Save**
- אם הקובץ השתנה בדיסק מאז שנפתח, הפאנל מזהיר ומאפשר לדרוס או לבטל
- **Discard** מבטל את העריכות
- לחיצה על הנתיב בכותרת מעתיקה נתיב מוחלט

לחיצה ימנית על נתיב פותחת תפריט הקשר:

- **Attach as context** - מוסיף את הקובץ לפרומפט הבא
- **Open in** - פותח בעורך חיצוני מותקן, כמו VS Code, Cursor או Zed
- **Show in Explorer** ב-Windows, **Show in Finder** ב-macOS
- **Copy path**

| **Summary** | רק תגובות סופיות ושינויים | סריקה מהירה של כמה סשנים |

## סקירת שינויים - diff view

<div class="plain-language">
<h4>במילים פשוטות</h4>

<p>אחרי ש-Claude נוגע בקבצים מופיע מחוון קטן כמו <code>+12 -1</code> - כלומר 12 שורות נוספו ואחת נמחקה. לחיצה עליו פותחת את מסך הסקירה.</p>

## תצוגה מקדימה ודפדפן

Claude יכול להפעיל שרת פיתוח ולפתוח אותו בפאנל הדפדפן. זה עובד גם לאפליקציות ווב וגם לשרתי backend - הוא יכול לבדוק endpoints, לקרוא לוגים ולתקן מה שהוא מוצא. ברוב המקרים הוא מפעיל את השרת מעצמו אחרי עריכת קבצים.

מה שאפשר לעשות מהפאנל:

- לתקשר עם האפליקציה הרצה ישירות
- לראות את Claude מאמת את עצמו - צילומי מסך, בדיקת DOM, לחיצה על אלמנטים, מילוי טפסים
- להפעיל ולעצור שרתים מתפריט השרת בסרגל הסשן
- **Persist sessions** - שמירת עוגיות ו-local storage בין הפעלות מחדש, כדי לא להתחבר מחדש בכל פעם

### קובץ launch.json

התצורה נשמרת ב-`.claude/launch.json` בשורש התיקייה שנבחרה בפתיחת הסשן. שים לב: אם בחרת תיקיית אב, תת-תיקיות עם שרת משלהן **לא יזוהו אוטומטית**.

```json
{
  "version": "0.0.1",
  "configurations": [
    {
      "name": "my-app",
      "runtimeExecutable": "npm",
      "runtimeArgs": ["run", "dev"],
      "port": 3000
    }
  ]
}
```

השדות בכל ערך במערך:

| השדה | טיפוס | משמעות |
|------|--------|---------|
| `name` | מחרוזת | מזהה ייחודי לשרת |
| `runtimeExecutable` | מחרוזת | הפקודה - `npm`, `yarn`, `node` |
| `runtimeArgs` | מערך | ארגומנטים, למשל `["run", "dev"]` |
| `port` | מספר | הפורט. ברירת מחדל 3000 |
| `cwd` | מחרוזת | תיקיית עבודה יחסית לשורש |
| `env` | אובייקט | משתני סביבה נוספים |
| `autoPort` | בוליאני | טיפול בהתנגשות פורטים |
| `program` | מחרוזת | סקריפט להרצה ישירה עם `node` |
| `args` | מערך | ארגומנטים ל-`program` |
| `url` | מחרוזת | כתובת חלופית לפתיחה |

> **אזהרת אבטחה:** אל תשים סודות ב-`env` - הקובץ הזה נכנס ל-git. סודות מגדירים בעורך הסביבה המקומית.

### autoVerify

כברירת מחדל Claude **מאמת את עצמו אחרי כל עריכה**: מצלם מסך, בודק שגיאות, מוודא שהשינוי עובד. כיבוי לפרויקט מסוים:

```json
{
  "version": "0.0.1",
  "autoVerify": false,
  "configurations": [ ... ]
}
```

גם כשזה כבוי, הכלים עדיין זמינים - אפשר לבקש אימות ידנית בכל רגע. ההבדל הוא רק אם זה קורה אוטומטית.

### התנגשות פורטים

| ערך `autoPort` | ההתנהגות |
|----------------|-----------|
| `true` | מוצא פורט פנוי לבד. מתאים לרוב שרתי הפיתוח |
| `false` | נכשל בשגיאה. כשהפורט קריטי, למשל ל-OAuth callback או ל-CORS |
| לא מוגדר | שואל אותך פעם אחת ושומר את התשובה |

כשנבחר פורט אחר, הוא מועבר לשרת דרך משתנה הסביבה `PORT`.

### גלישה באתרים חיצוניים

פאנל הדפדפן הוא דפדפן עם לשוניות - אפשר לפתוח בו תיעוד או מערכת ניהול משימות לצד האפליקציה. נפתח ב-**Ctrl+Shift+B**.

שתי שכבות בטיחות מעל מה שקיים בתצוגה המקדימה:

1. **מסווגי בטיחות** בודקים כל פעולת כתיבה של Claude בדף חיצוני - לחיצה, הקלדה - **בכל מצב הרשאה**. אלה אותם מסווגים של auto mode, וכשהם מסמנים פעולה מקבלים בקשת אישור ללא קשר למצב
2. **בדיקת רשימת דומיינים מותרים** לפני ניווט לאתר חדש, בכל המצבים חוץ מ-Auto ו-Bypass

בפעם הראשונה שClaude פועל באתר חיצוני מופיע כרטיס אישור: **Allow once**, **Always allow** או **Deny**. כל אתר דורש אישור נפרד, **כולל תת-דומיינים**. שרתי פיתוח מקומיים וקבצי הפרויקט לא דורשים אישור בכלל.

גם באתר מאושר, Claude לא יבצע רכישות, לא ייצור חשבונות ולא יעקוף CAPTCHA בלי קלט ממך.

### הדפדפן המובנה מול תוסף Chrome

הבחנה חשובה: **פאנל הדפדפן משתמש בפרופיל נקי**, נפרד מהדפדפן האישי שלך, בלי ההתחברויות וההיסטוריה שלך.

- לבנייה ובדיקה של האפליקציה, ולאתרים שלא דורשים זהות - הפאנל המובנה
- כשרוצים ש-Claude יפעל **בשמך** בהתחברויות הקיימות שלך - תוסף Claude in Chrome

### הגבלות ארגוניות

| ההגדרה | ההשפעה |
|---------|---------|
| `browserExternalPageTools` | ערך `"disabled"` מונע מ-Claude לקרוא או לפעול בדפים חיצוניים. המשתמש עדיין יכול לגלוש בעצמו |
| `disableBrowserExternalNavigation` | ערך `true` חוסם ניווט חיצוני לגמרי, כולל אתרים ברשימה המותרת. תצוגות localhost ממשיכות לעבוד |

## ניטור Pull Request

אחרי פתיחת PR מופיע סרגל סטטוס CI בסשן. Claude Code משתמש ב-GitHub CLI כדי לתשאל את תוצאות הבדיקות ולהציף כשלים.

| המתג | מה עושה |
|------|----------|
| **Auto-fix** | Claude מנסה לתקן בדיקות CI שנכשלות - קורא את הפלט ומתקן בלולאה |
| **Auto-merge** | Claude ממזג את ה-PR ברגע שכל הבדיקות עוברות. שיטת המיזוג היא squash |

כדי ש-Auto-merge יעבוד, **צריך להפעיל auto-merge קודם בהגדרות המאגר ב-GitHub**. בלי זה Claude לא יוכל למזג.

האפליקציה שולחת התראת מערכת כשה-CI מסתיים. אפשר גם להפעיל ארכוב אוטומטי של הסשן כשה-PR ממוזג או נסגר.

> דרישה: **GitHub CLI (`gh`) מותקן ומאומת**. אם הוא חסר, האפליקציה תציע להתקין אותו בפעם הראשונה שתנסה ליצור PR.

## סשנים מקבילים ובידוד Git

<div class="plain-language">
<h4>במילים פשוטות</h4>

<p>זו היכולת הכי משמעותית של הדסקטופ. אפשר לפתוח כמה שיחות במקביל, וכל אחת מקבלת <strong>עותק מבודד משלה של הפרויקט</strong>.</p>

<p>למה זה חשוב? כי בלי זה, שני Claude שעובדים בו-זמנית על אותה תיקייה היו דורסים זה את זה. עם worktree, סשן א' יכול לשבור הכל בניסיון שלו וסשן ב' אפילו לא ידע. רק כשאתה מחליט למזג - השינויים נפגשים.</p>

<p>בטרמינל זה קיים גם, אבל שם צריך לבקש את זה במפורש עם דגל <code>--worktree</code>. בדסקטופ זה קורה מעצמו.</p>
</div>

**+ New session** בסרגל הצד, או `Ctrl+N`. מחזור בין סשנים ב-`Ctrl+Tab`.

במאגרי Git, **כל סשן מקבל worktree מבודד משלו** - עותק נפרד עם ענף משלו. שינויים בסשן אחד לא משפיעים על האחרים עד לקומיט.

### תצוגה מפוצלת

מחזיקים `Ctrl` ולוחצים על סשן בסרגל הצד - הוא נפתח בפאנל שני לצד הקיים. כשהפיצול פעיל, לחיצה על סשן אחר מחליפה את הפאנל **הממוקד**. `Ctrl+\` סוגר את הממוקד וחוזר לסשן יחיד.

### ניהול ה-worktrees

- ברירת המחדל: `<שורש-הפרויקט>/.claude/worktrees/`
- ניתן לשינוי ב-`Settings → Claude Code` תחת `Worktree location`
- אפשר להגדיר **קידומת לשם הענף**, שימושי כדי לזהות ענפים שClaude יצר
- למחיקת worktree: מרחפים מעל הסשן בסרגל הצד ולוחצים על סמל הארכוב
- **Auto-archive after PR merge or close** בהגדרות מארכב אוטומטית. חל רק על סשנים מקומיים שסיימו לרוץ

כדי להכניס קבצים שנמצאים ב-gitignore - למשל `.env` - ל-worktrees חדשים, יוצרים קובץ `.worktreeinclude` בשורש הפרויקט. בלי זה, סשן חדש לא יראה את משתני הסביבה שלך.

### סינון וניהול

- פקדים בראש סרגל הצד מסננים לפי סטטוס, פרויקט או סביבה, ומקבצים לפי פרויקט
- שינוי שם: לחיצה על כותרת הסשן בסרגל העליון
- האפליקציה שולחת התראת מערכת כשסשן מסיים משימה **ואתה לא צופה בו כרגע**

כשחלון ההקשר מתמלא, Claude מסכם את השיחה וממשיך אוטומטית. `/compact` מפעיל את זה מוקדם יותר ידנית.

## עבודה בין סשנים

### צ'אט צדדי

`Ctrl+;` או הקלדת `/btw` בתיבת הפרומפט.

צ'אט צדדי מאפשר לשאול שאלה **שמשתמשת בהקשר של הסשן אבל לא מוסיפה אליו כלום**. מתאים להבנת קטע קוד או לבדיקת הנחה, בלי להסיט את השיחה הראשית.

הוא קורא את כל מה שקרה בשרשור הראשי עד לאותה נקודה. זמין ב-Local, SSH ו-WSL.

> מגבלה שכדאי לדעת: **צ'אטים צדדיים לא נשמרים לדיסק**. אחרי סגירת האפליקציה אי אפשר לחזור אליהם.

### פאנל המשימות

מציג את עבודת הרקע שרצה **בתוך הסשן הנוכחי**: סוכני משנה, פקודות shell ברקע, ו-dynamic workflows. לחיצה על ערך מציגה את הפלט שלו או עוצרת אותו.

### שליטה בסשנים אחרים דרך שיחה

Claude יכול לרשום את שאר הסשנים בלשונית Code, לקרוא מה כל אחד עשה, ולשלוח הודעות ביניהם. שואלים בשפה חופשית:

- "איזה סשן נגע ברפקטור של האימות?"

אפשר גם לבקש ממנו לשנות שם או לארכב סשן. הוא מארכב בדיוק כמו סמל הארכוב בסרגל - למשל "תנקה את הסשנים שה-PR שלהם כבר מוזג".

### העברה למשטח אחר

תפריט **Continue in**, מסמל ה-VS Code בפינה הימנית התחתונה של סרגל הסשן:

- **Claude Code on the Web** - דוחף את הענף, מייצר סיכום של השיחה, ופותח סשן ענן עם ההקשר המלא. **דורש עץ עבודה נקי**, ולא זמין לסשני SSH
- **Your IDE** - פותח את הפרויקט בסביבת פיתוח נתמכת, בתיקייה הנוכחית

בכיוון ההפוך, מהטרמינל לדסקטופ, יש את הפקודה `/desktop`. שלוש מגבלות שכדאי לדעת עליה מראש:

1. זמינה ב-macOS וב-**Windows x64 בלבד**
2. דורשת התחברות עם מנוי - **לא עובדת עם אימות במפתח API**
3. לא עובדת על Amazon Bedrock, Google Cloud Agent Platform או Microsoft Foundry

### סשנים מ-Dispatch

Dispatch היא שיחה מתמשכת עם Claude שיושבת בלשונית Cowork. שולחים לה משימה והיא מחליטה איך לטפל.

הסשן מופיע בסרגל הצד עם תג **Dispatch**, ומגיעה התראה לטלפון כשהוא מסיים או צריך אישור.

## מצבי הרשאה

<div class="plain-language">
<h4>במילים פשוטות</h4>

<p>מצב ההרשאה עונה על שאלה אחת: <strong>מה Claude מותר לעשות בלי לשאול אותך קודם</strong>. זה הבורר שליד כפתור השליחה, ואפשר להחליף אותו באמצע השיחה.</p>

<p>הכלל המעשי: מתחילים משימה מורכבת ב-<code>Plan</code> כדי לראות מה הוא מתכנן, ואחרי שמאשרים עוברים ל-<code>Accept edits</code> לביצוע.</p>
</div>

| המצב | מפתח בהגדרות | ההתנהגות |
|------|---------------|-----------|
| **Manual** | `default` | שואל לפני כל עריכת קובץ וכל פקודה. רואים diff ומאשרים או דוחים |
| **Accept edits** | `acceptEdits` | מאשר אוטומטית עריכות קבצים ופקודות מערכת קבצים נפוצות כמו `mkdir` ו-`mv`, אבל עדיין שואל על פקודות טרמינל אחרות |
| **Plan** | `plan` | קורא ובודק, ואז מציע תוכנית **בלי לגעת בקוד** |
| **Auto** | `auto` | מבצע הכל עם בדיקות בטיחות ברקע שמאמתות התאמה לבקשה |
| **Bypass permissions** | `bypassPermissions` | בלי בקשות אישור. מקביל ל-`--dangerously-skip-permissions`. **רק בקונטיינר או VM מבודד** |

### היכן נמצא מה

- **Auto** מופיע מעצמו כשהחשבון עומד בתנאים. **אין לו מתג נפרד בהגדרות**
- **Bypass permissions** ב-Pro ו-Max: מפעילים ב-`Settings → Claude Code` תחת `Allow bypass permissions mode`. ב-Team ו-Enterprise אין מתג, ומדיניות הארגון קובעת

שים לב: זה `Settings → Claude Code`, לא `Settings → General`. תחת `General` יושב ה-computer use, וזו טעות קלה.

גם ב-Bypass יש דברים ש-Claude עדיין שואל עליהם: הפעולות שאף מצב לא מאשר אוטומטית, מסווגי הבטיחות בפעולה על אתרים חיצוניים, ופעולות דסקטופ כמו ארכוב סשן.

### ברירת מחדל וזיכרון

`permissions.defaultMode` בקובץ ההגדרות קובע ברירת מחדל לסשנים חדשים.

אבל: **מצב שבחרת בבורר נזכר לפי תיקייה וגובר על ברירת המחדל** עבור אותה תיקייה. היוצא מן הכלל הוא `Plan`, שחל על הסשן הנוכחי בלבד ולא נשמר.

### תנאים ל-Auto mode

- זמין לכל המשתמשים ב-Anthropic API
- דורש **Opus 4.6 ומעלה, Sonnet 4.6 ומעלה, או כל מודל Fable**. לא עובד ב-Haiku או במודלים ישנים
- מנהלי ארגון יכולים לכבות עם `disableAutoMode` ב-managed settings

### הבדלים לפי סביבה

- **סשני ענן** תומכים ב-Accept edits, Plan ו-Auto. `Accept edits` שם מקביל למצב `default`, כי ענן מאשר עריכות מראש. **Bypass לא זמין בענן**
- המצב `dontAsk` קיים **רק ב-CLI**

גרסאות ישנות של לשונית Code קראו למצבים האלה בשמות אחרים: `Ask permissions`, `Auto accept edits` ו-`Plan mode`.

## הרחבות - connectors, skills, plugins

**Customize** בסרגל הצד מרכז את שלושתם במקום אחד.

> נקודה מבלבלת ששווה לשים לב אליה: לשונית **Cowork** שואבת את ה-skills, ה-plugins וה-connectors שלה **מתצורת Customize הזו**, שמסתנכרנת דרך חשבון claude.ai - ולא מתיקיית `~/.claude` של ה-CLI. כלומר Code ו-Cowork לא בהכרח רואים את אותו דבר.

### Connectors

Connectors הם **שרתי MCP עם אשף התקנה גרפי**. Google Calendar, Slack, GitHub, Linear, Notion ועוד.

- כפתור `+` ליד תיבת הפרומפט, ואז `Connectors`
- אפשר להוסיף לפני או תוך כדי סשן
- זמין ב-**Local ו-SSH בלבד**. בענן וב-WSL כפתור ה-`+` לא זמין, ושם מגדירים connectors ברמת ה-routine
- ניהול וניתוק: `Settings → Connectors`, או `Manage connectors` מהתפריט

לשירותים שאין להם connector - מוסיפים שרת MCP ידנית דרך קבצי ההגדרות.

### Skills

- הקלדת `/` בתיבה, או `+` ואז `Slash commands`, פותחת דפדפן של הפקודות הזמינות: פקודות מובנות, skills אישיים, skills של הפרויקט, ו-skills מכל plugin מותקן
- אפשר לשלוח פקודה **בזמן ש-Claude עובד**, כמו כל הודעה אחרת

מלכודת ב-SSH: **סשן SSH קורא את `~/.claude/skills/` מתיקיית הבית של המכונה המרוחקת**, לא מזו שלך. סשני ענן טוענים את ה-skills שמופעלים בחשבון claude.ai.

### Plugins

- `+` ואז `Plugins` מציג את המותקנים. `Add plugin` פותח את דפדפן התוספים, כולל המרקטפלייס הרשמי של Anthropic
- `Manage plugins` להפעלה, כיבוי והסרה
- אפשר לשייך לחשבון, לפרויקט מסוים, או מקומי בלבד

מגבלה: **plugins שהותקנו בדסקטופ לא זמינים בסשני ענן**, ואינם זמינים כלל ב-WSL. כדי להשתמש ב-plugin בסשן ענן, מצהירים עליו ב-`.claude/settings.json` של המאגר תחת `enabledPlugins`, וכך הוא מותקן בתחילת הסשן.

### MCP - קדימויות שכדאי להכיר

כאן יש התנהגות שסוטה מהכללים הרגילים של ה-CLI, ושווה לדעת עליה מראש:

1. האפליקציה טוענת שרתי MCP מ-`claude_desktop_config.json` **גם לתוך סשני Code מקומיים**, לצד `~/.claude.json` ו-`.mcp.json`
2. אם אותו שם שרת מוגדר גם ב-`claude_desktop_config.json` וגם ב-`~/.claude.json` או `.mcp.json` - **הגדרת `claude_desktop_config.json` מנצחת**
3. כששרת stdio באותו שם מוגדר גם ב-`~/.claude.json` (רמת משתמש) וגם ב-`.mcp.json` - לשונית Code מעדיפה את `~/.claude.json`, **בניגוד להיררכיית ה-scope הרגילה של ה-CLI**

בכיוון ההפוך: **ה-CLI העצמאי לא קורא את `claude_desktop_config.json` בכלל**. כדי להעתיק את השרתים האלה אליו מריצים `claude mcp add-from-claude-desktop` (ב-macOS וב-WSL).

## Computer use

<div class="plain-language">
<h4>במילים פשוטות</h4>

<p>Computer use זו היכולת של Claude <strong>לראות את המסך שלך ולהזיז את העכבר</strong> - לפתוח תוכנות, ללחוץ, להקליד. בשביל דברים שאין להם ממשק אחר.</p>

<p>זה גם המקום שדורש הכי הרבה זהירות בכל האפליקציה, כי בניגוד לכלי ה-Bash שרץ בארגז חול, כאן Claude פועל על שולחן העבודה האמיתי שלך. לכן זה כבוי כברירת מחדל, ולכן יש שכבות הגנה.</p>
</div>

> זו **תצוגה מקדימה מחקרית** ב-macOS וב-Windows, שדורשת מנוי **Pro או Max**. אינה זמינה ב-Team או ב-Enterprise, ואינה זמינה בגרסת הלינוקס. האפליקציה חייבת לרוץ.

### הפעלה

1. עדכון האפליקציה לגרסה האחרונה והפעלה מחדש
2. `Settings → General` תחת `Desktop app`, ומתג **Computer use**
3. ב-**Windows** - זהו, המתג נכנס לתוקף מיד
4. ב-**macOS** צריך שתי הרשאות מערכת נוספות:
   - **Accessibility** - כדי ללחוץ, להקליד ולגלול
   - **Screen Recording** - כדי לראות את המסך

עמוד ההגדרות מציג את הסטטוס של כל אחת. אם אחת נדחתה, לחיצה על התג פותחת את החלונית המתאימה ב-System Settings.

### שכבות ההרשאה לפי סוג אפליקציה

בפעם הראשונה שClaude צריך אפליקציה מופיעה בקשה בסשן: **Allow for this session** או **Deny**. האישור תקף לסשן הנוכחי - או ל-30 דקות בסשנים שנפתחו מ-Dispatch.

הבקשה מציגה גם **איזו רמת שליטה** Claude מקבל. הרמות קבועות לפי קטגוריית האפליקציה ו**אי אפשר לשנות אותן**:

| הרמה | מה מותר | על מה חל |
|------|----------|-----------|
| **View only** | רק לראות בצילומי מסך | דפדפנים, פלטפורמות מסחר |
| **Click only** | ללחוץ ולגלול, בלי הקלדה וקיצורי מקלדת | טרמינלים, סביבות פיתוח |
| **Full control** | לחיצה, הקלדה, גרירה, קיצורים | כל השאר |

אפליקציות עם טווח השפעה רחב - טרמינל, סייר הקבצים, הגדרות המערכת - מציגות אזהרה נוספת בבקשה.

### שתי הגדרות נוספות

תחת `Settings → General`:

- **Denied apps** - אפליקציות שיידחו בלי לשאול. Claude עדיין יכול להשפיע עליהן בעקיפין דרך אפליקציה מאושרת, אבל לא לתקשר איתן ישירות
- **Unhide apps when Claude finishes** - בזמן ש-Claude עובד, שאר החלונות מוסתרים כדי שיפעל רק על האפליקציה המאושרת. בסיום הם משוחזרים, אלא אם כיבית את זה

### מנגנוני ההגנה

- **אישור לכל אפליקציה בנפרד**
- **אזהרות מיוחדות** לאפליקציות בעלות גישה רחבה
- **הטרמינל מוחרג מצילומי המסך** - Claude לא רואה את הפלט שלו, מה שמונע לולאות משוב
- **מקש `Esc` גלובלי** עוצר את computer use מכל מקום. הלחיצה נבלעת, כדי שלא ניתן יהיה להזריק אותה
- **נעילה ברמת המכונה** - רק סשן אחד יכול לשלוט במסך בכל רגע. אם סשן קרס, הנעילה משתחררת כשהתהליך מת

> Claude בודק כל פעולה ומסמן ניסיונות הזרקת פרומפט מתוכן שמופיע על המסך, אבל **גבול האמון כאן שונה** מזה של כלי ה-Bash המבודד. זה רץ על שולחן העבודה האמיתי עם גישה לכל מה שאישרת.

### סדר העדפת הכלים

Claude מנסה תמיד את הכלי המדויק ביותר קודם, ו-computer use הוא הרחב והאיטי ביותר:

1. **Connector** לשירות, אם קיים
2. **Bash**, אם זו פקודת מעטפת
3. **Claude in Chrome**, אם זו עבודת דפדפן והתוסף מותקן
4. **פאנל ה-iOS Simulator**, אם זו הרצת אפליקציית iOS. הוא **לא** משתמש בשליטת מסך
5. **Computer use**, רק אם שום דבר מהנ"ל לא מתאים

שכבות ההרשאה מחזקות את הסדר הזה בכוונה: דפדפנים חסומים ל-view-only וטרמינלים ל-click-only, מה שמכוון את Claude לכלי הייעודי גם כש-computer use פעיל. שליטת מסך שמורה למה ששום כלי אחר לא מגיע אליו - אפליקציות מקומיות, לוחות בקרה של חומרה, וכלים סגורים בלי API.

## משימות מתוזמנות

<div class="plain-language">
<h4>במילים פשוטות</h4>

<p>משימה מתוזמנת היא פרומפט ש<strong>רץ מעצמו בשעה שקבעת</strong> - סקירת קוד יומית בבוקר, בדיקת תלויות שבועית, תדריך שמושך מהיומן ומהמייל.</p>

<p>המגבלה המרכזית: זה רץ <strong>רק כשהאפליקציה פתוחה והמחשב ער</strong>. אם המחשב ישן - זה לא קרה. לעבודה שחייבת לרוץ גם כשהמחשב כבוי יש routines בענן.</p>
</div>

הכל דרך **Routines** בסרגל הצד. אותו עמוד יוצר גם משימות מקומיות וגם routines בענן.

### שלוש דרכי התזמון - השוואה

| | **ענן** | **דסקטופ** | **`/loop`** |
|---|---------|-------------|-------------|
| רץ על | תשתית Anthropic | המכונה שלך | המכונה שלך |
| דורש מחשב דלוק | לא | כן | כן |
| דורש סשן פתוח | לא | לא | כן |
| שורד הפעלה מחדש | כן | כן | רק ב-`--resume` |
| גישה לקבצים מקומיים | לא, שכפול טרי | כן | כן |
| בקשות אישור | אין, רץ אוטונומית | ניתן להגדרה למשימה | יורש מהסשן |
| מרווח מינימלי | שעה | דקה | דקה |

### יצירת משימה

`New routine` ואז `Local`. השדות:

| השדה | הערות |
|------|--------|
| `Name` | מומר ל-kebab-case ומשמש כשם התיקייה בדיסק. חייב להיות ייחודי |
| `Description` | תקציר שמופיע ברשימה |
| `Instructions` | מה שClaude יעשה. כולל בוררים למצב הרשאה ולמודל, ומתחת - בחירת תיקייה ומתג worktree |
| `Schedule` | תדירות |

**חובה לבחור תיקייה** לפני שמירה. אם היא לא מסומנת כמהימנה, האפליקציה תבקש לאשר.

אפשר גם ליצור בשיחה רגילה: "תקים סקירת קוד יומית ב-9 בבוקר" יוצר משימה חוזרת, ו"תזכיר לי מחר ב-15:00 לבדוק את הדיפלוי" יוצר משימה חד-פעמית שמכבה את עצמה אחרי שהיא פועלת.

### אפשרויות תזמון

- **Manual** - בלי לוח זמנים, רץ רק בלחיצה על `Run now`. שימושי לשמירת פרומפט שמפעילים לפי דרישה
- **Hourly** - כל שעה
- **Daily** - עם בורר שעה, ברירת מחדל 9:00 מקומי
- **Weekdays** - כמו Daily, בלי שבת וראשון
- **Weekly** - בורר שעה ובורר יום

למרווחים שהבורר לא מציע - כל 15 דקות, ראשון לחודש, מועד עתידי יחיד - מבקשים מ-Claude בשפה חופשית בכל סשן דסקטופ.

### איך זה רץ בפועל

- האפליקציה בודקת את הלוח **כל דקה** כל עוד היא פתוחה, ופותחת סשן חדש כשמשימה מגיעה
- לכל משימה יש **השהיה דטרמיניסטית** של כמה דקות אחרי השעה, כדי לפזר עומס. אותה משימה תמיד מתחילה באותו היסט
- מגיעה התראה, והסשן מופיע תחת **Scheduled** בסרגל הצד
- Claude יכול לערוך קבצים, להריץ פקודות, ליצור קומיטים ולפתוח PR - כמו בכל סשן
- **הוא לא יכול** לשלוח או לקבל הודעות בין סשני דסקטופ

אם המחשב ישן בשעה המיועדת - הריצה מדולגת. `Keep computer awake` בהגדרות תחת `Desktop app → General` מונע שינה מחוסר פעילות, אבל **סגירת מכסה עדיין מרדימה**.

### ריצות שהוחמצו

כשהאפליקציה עולה או המחשב מתעורר, היא בודקת אם משימה החמיצה ריצות **בשבעת הימים האחרונים**. אם כן - היא מריצה **בדיוק ריצת השלמה אחת**, למועד האחרון שהוחמץ, וזורקת את כל השאר. משימה יומית שהחמיצה שישה ימים תרוץ פעם אחת.

זו נקודה שמשפיעה על ניסוח הפרומפט:

> משימה שתוזמנה ל-9:00 עלולה לרוץ ב-23:00 אם המחשב ישן כל היום. אם התזמון חשוב, מכניסים את זה לפרומפט עצמו - למשל: "תסקור רק את הקומיטים של היום. אם השעה אחרי 17:00, דלג על הסקירה ורק סכם מה הוחמץ."

### הרשאות במשימות מתוזמנות

- לכל משימה מצב הרשאה משלה
- כללי ה-allow מ-`~/.claude/settings.json` חלים גם עליהן
- **אם משימה רצה ב-Manual וחסרה לה הרשאה - הריצה נתקעת** עד שתאשר. הסשן נשאר פתוח בסרגל כדי שתוכל לענות מאוחר יותר

הדרך למנוע תקיעות: ללחוץ `Run now` מיד אחרי היצירה, לעקוב אחרי בקשות האישור, ולבחור "always allow" בכל אחת. ריצות עתידיות יאשרו את אותם כלים אוטומטית.

יוצאי דופן שתמיד יתקעו: כלי connector שהארגון הגדיר כ-`ask`, וכלי MCP שמסומנים `requiresUserInteraction`. הם מבקשים אישור בכל קריאה ואין להם אפשרות always-allow.

### ניהול

לחיצה על משימה פותחת את עמוד הפרטים:

- **Run now** - הרצה מיידית
- **Status** - החלפה בין Active ל-Paused, בלי למחוק
- **Edit** - שינוי הוראות, לוח זמנים, תיקייה והגדרות
- **Review history** - כל הריצות, כולל מדולגות. ריחוף על ריצה מדולגת מסביר למה: המחשב ישן, הריצה הקודמת עוד רצה, או שמשימות אחרות כבר רצו
- **Review allowed permissions** - צפייה וביטול של אישורי כלים שנשמרו
- **Delete** - מחיקה וארכוב כל הסשנים שהיא יצרה. תיבת סימון `Also delete files on disk` מוחקת גם את הקבצים

### אחסון בדיסק

```
~/.claude/scheduled-tasks/<task-name>/SKILL.md
```

או תחת `CLAUDE_CONFIG_DIR` אם הוגדר. הקובץ משתמש ב-frontmatter מסוג YAML עבור `name` ו-`description`, והפרומפט הוא גוף הקובץ. שינויים נכנסים לתוקף בריצה הבאה.

מה ש**לא** נמצא בקובץ: לוח הזמנים, התיקייה, המודל ומצב ההפעלה. את אלה משנים דרך טופס העריכה או בבקשה מ-Claude.

משימה יכולה גם **לשנות את התזמון של עצמה** תוך כדי ריצה, דרך כלי ה-MCP בשם `update_scheduled_task` - למשל לתזמן סקירה מוקדם יותר כשהיא מזהה שנוצר ענף שחרור.

## הגדרות - מה בממשק ומה רק בקובץ

אפליקציית הדסקטופ **קוראת את אותם קבצי הגדרות כמו ה-CLI**, בסדר העדיפויות הרגיל: managed settings, אחר כך רמת פרויקט, אחר כך רמת משתמש.

מה שיש לו מתג גרפי:

| ההגדרה | היכן |
|---------|------|
| Computer use, Denied apps, Unhide apps | `Settings → General` תחת `Desktop app` |
| Keep computer awake | `Settings → General` תחת `Desktop app` |
| Allow bypass permissions mode | `Settings → Claude Code` |
| Worktree location, Branch prefix | `Settings → Claude Code` |
| Auto-archive after PR merge | `Settings → Claude Code` |
| כיבוי הדפדפן, ניקוי נתוני גלישה | `Settings → Claude Code` |
| Connectors | `Settings → Connectors` |
| מודל, מצב הרשאה, רמת מאמץ | בוררים ליד כפתור השליחה |
| Persist sessions בדפדפן | תפריט השרת |
| autoVerify | תפריט השרת, או `.claude/launch.json` |

מה שדורש עריכת קובץ ידנית: כללי הרשאות מפורטים, hooks, subagents, `enabledPlugins`, `sshConfigs`, וכל ההגדרות הארגוניות.

> הסיבה: **פקודות שפותחות חלונית אינטראקטיבית בטרמינל מתנהגות אחרת בדסקטופ**. פקודות בלי צורת ארגומנט, כמו `/permissions`, פשוט עונות שהן לא זמינות בסביבה הזו. `/config` פותח את `Settings → Claude Code`, וטקסט אחריה **מתעלמים ממנו** - כלומר `/config theme=dark` לא יעשה כלום.

### שליטה ארגונית

דרך [קונסולת הניהול](https://claude.ai/admin-settings/claude-code):

- **Code in the desktop** - האם משתמשי הארגון יכולים לגשת ללשונית Code בכלל
- **Code in the web** - סשני ווב
- **Remote Control**
- **Disable Bypass permissions mode**

מפתחות ב-managed settings:

| המפתח | מה עושה |
|--------|----------|
| `permissions.disableBypassPermissionsMode` | ערך `"disable"` מונע הפעלת מצב bypass |
| `disableAutoMode` | ערך `"disable"` מסיר את Auto מהבורר |
| `autoMode` | התאמת מה שהמסווג של auto mode סומך עליו וחוסם |
| `browserExternalPageTools` | ערך `"disabled"` מכבה את כלי Claude בדפים חיצוניים |
| `disableBrowserExternalNavigation` | ערך `true` חוסם ניווט חיצוני לגמרי |
| `sshHostAllowlist` | מגביל את יעדי ה-SSH |

## דסקטופ מול טרמינל

<p>אפשר להריץ את שניהם בו-זמנית, אפילו על אותו פרויקט. היסטוריית השיחות נפרדת, אבל ההגדרות משותפות לגמרי - אותו CLAUDE.md, אותם skills, אותם שרתי MCP.</p>

### מקבילות לדגלים של ה-CLI

| ב-CLI | המקבילה בדסקטופ |
|-------|------------------|
| `--model sonnet` | תפריט המודל ליד כפתור השליחה |
| `--resume`, `--continue` | לחיצה על סשן בסרגל הצד |
| `--permission-mode` | בורר המצב ליד כפתור השליחה |
| `--dangerously-skip-permissions` | מצב Bypass, אחרי הפעלה בהגדרות |
| `--add-dir` | כפתור `+` בסשני ענן, לצירוף מאגרים |
| `--allowedTools`, `--disallowedTools` | אין מקבילה לסשן. כללי ההרשאות בקבצים עדיין חלים |
| `--verbose` | מצב התצוגה Verbose |
| `--print`, `--output-format` | **אין**. הדסקטופ אינטראקטיבי בלבד |
| `ANTHROPIC_MODEL` | תפריט המודל |
| `MAX_THINKING_TOKENS` | עורך הסביבה המקומית |

### מה שהדסקטופ נותן ואין בטרמינל

- מערכת פאנלים נגררים ותצוגה מפוצלת
- דפדפן מובנה עם לשוניות, ופאנל תצוגה מקדימה
- סקירת diff ויזואלית עם הערות על שורות
- הכלי Review code
- worktrees **אוטומטיים** בלי דגל
- אשף גרפי ל-connectors, ומנהל plugins גרפי
- צירוף תמונות ו-PDF לפרומפט
- השלמה אוטומטית ב-`@mention`
- משימות מתוזמנות מקומיות
- פאנל iOS Simulator, שנפתח אוטומטית
- סשני Dispatch
- התראות מערכת

### מה שקיים רק בטרמינל

- **הרצה לא אינטראקטיבית** - `--print` וה-Agent SDK. זה ההבדל הגדול לאוטומציה
- **מצב ההרשאה `dontAsk`**
- **Agent teams** - צוותי סוכנים מתואמים עם מוביל שמחלק משימות. לעומת זאת **dynamic workflows כן רצים בדסקטופ**
- **ספקים חיצוניים** - Bedrock, Google Cloud Agent Platform ו-Microsoft Foundry. הדסקטופ מתחבר ל-API של Anthropic כברירת מחדל
- **הצעות קוד inline** בסגנון השלמה אוטומטית - לא קיימות בדסקטופ בכלל
- פקודות שפותחות חלונית בטרמינל
- **`/branch` ו-`--fork-session`** - יצירת עותק של שיחה. בדסקטופ פותחים סשן חדש במקום
- **`/cd`** - החלפת תיקייה תוך כדי סשן

### מה משותף

- קבצי `CLAUDE.md` ו-`CLAUDE.local.md` של הפרויקט
- שרתי MCP מ-`~/.claude.json` ומ-`.mcp.json`
- hooks ו-skills מההגדרות
- קבצי ההגדרות עצמם, כולל כללי הרשאות
- אותם מודלים בדיוק

## תקלות נפוצות

| התסמין | הסיבה והפתרון |
|---------|-----------------|
| `Error 403` בלשונית Code | להתנתק ולהתחבר מחדש - זה התיקון הנפוץ ביותר. לוודא מנוי פעיל. אם ה-CLI עובד והדסקטופ לא, **לצאת מהאפליקציה לגמרי** ולא רק לסגור חלון |
| מסך ריק או תקוע בעלייה | הפעלה מחדש, בדיקת עדכונים ממתינים. ברשת מנוהלת - לוודא שהחומה מאפשרת את מארחי ה-CDN. ב-Windows לבדוק לוגים ב-Event Viewer תחת `Windows Logs → Application` |
| `Failed to load session` | התיקייה כבר לא קיימת, המאגר דורש Git LFS שלא מותקן, או הרשאות קבצים חוסמות |
| Claude לא מוצא `npm` או `node` | ירושת סביבה חלקית. לוודא שהכלי עובד בטרמינל רגיל, ואז להגדיר את הנתיב **בעורך הסביבה המקומית** ולהפעיל מחדש |
| `Git is required` | ב-Windows - להתקין Git for Windows ולהפעיל מחדש את האפליקציה |
| `Git LFS is required` | להתקין מ-git-lfs.com, להריץ `git lfs install`, ולהפעיל מחדש |
| שרתי MCP לא עובדים ב-Windows | לבדוק תצורה, להפעיל מחדש, לוודא שהתהליך רץ ב-Task Manager, ולעבור על לוגי השרת |
| האפליקציה לא נסגרת | ב-Windows דרך Task Manager. ב-macOS דרך Force Quit |
| `PATH` לא התעדכן אחרי התקנה | לפתוח **חלון טרמינל חדש**. עדכוני PATH חלים רק על סשנים חדשים |
| שגיאת התקנה מקבילה ב-Windows | להריץ את המתקין כמנהל |
| `Branch doesn't exist yet` בפתיחה ב-CLI | סשן ענן יצר ענף שלא קיים מקומית. ללחוץ על שם הענף בסרגל להעתקה, ואז `git fetch origin <branch>` ו-`git checkout <branch>` |

לתקלות שאינן ייחודיות לדסקטופ - שגיאות `500`, `429`, `Prompt is too long` - ראה [troubleshooting.md](#/deep/troubleshooting).

בדיווח על תקלה כדאי לצרף: גרסת האפליקציה, מערכת ההפעלה, נוסח השגיאה המדויק ולוגים. **לפני פרסום לוג ציבורי כדאי לעבור עליו** - הוא עלול לכלול נתיבי קבצים ופרטים מהסביבה שלך.
